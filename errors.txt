Starter code bugs and fixes

1. CMake stopped before the build
   File: testbed_description/CMakeLists.txt
   Problem: The last line said ament_package without parentheses. CMake reported that it expected an opening parenthesis.
   Fix: Changed it to ament_package().
   Check: colcon build completed for all four packages on ROS 2 Humble.

2. The map files were missing from the install directory
   File: testbed_bringup/CMakeLists.txt
   Problem: CMake installed launch/ but skipped maps/. The map loader looks in the installed package for the map.
   Fix: Added maps/ to the install rule.
   Check: Both the YAML and PGM files were present in the installed package.

3. The map YAML pointed to the wrong image
   File: testbed_bringup/maps/testbed_world.yaml
   Problem: The image field pointed to wrong_path_testbed_world.pgm, which did not exist.
   Fix: Changed the image field to testbed_world.pgm.
   Check: The map server loaded the image and published the map on /map.

4. The simulated lidar could not see the walls at spawn
   File: testbed_description/urdf/testbed.gazebo
   Problem: The maximum range was 1.5 m. At the spawn pose, the scan had no obstacle returns, so AMCL had little to match against the map.
   Fix: Increased the simulated lidar maximum range to 10.0 m.
   Check: After restarting Gazebo, /scan reported a 10.0 m range and detected walls from the same spawn pose.

RViz setup for navigation

5. AMCL ignored the initial pose from RViz
   File: testbed_description/rviz/full_bringup.rviz
   Problem: RViz used odom as its fixed frame, so 2D Pose Estimate sent the pose in odom. AMCL expected it in map and ignored it.
   Fix: Changed the RViz fixed frame from odom to map.
   Check: AMCL accepted the pose after I set it again in RViz.
   Displays: Added the map, global and local costmaps, and global paths to RViz so I could see what the robot was planning.
